## 1. Executive Summary & Objective

In accordance with the approved CFIC × VoiceShield Hybrid Architecture, the **Risk Identification and Assessment Subsystem (RIAS)** performs semantic-risk analysis on incoming speech transcripts generated by the upstream ASR stage (OpenAI Whisper Base.en for English and IndicConformer checkpoints for Indian languages).

The primary objective of this evaluation is to empirically benchmark two lightweight pretrained LLM candidates on consumer laptop hardware (CPU execution, no dedicated GPU) to select **one** production candidate for the VoiceShield MVP:
- **Candidate A:** `Qwen/Qwen3.5-2B` (Quantization: GGUF `Q4_K_M`)
- **Candidate B:** `google/gemma-4-E2B-it` (Quantization: GGUF `Q4_K_M`)

### Architectural Boundaries & Locked Constraints
1. **LOCKED Upstream Subsystems:** Open-Vakgyata LID (Language Identification) and English Whisper Base.en are locked and containerized. They remain unmodified.
2. **Transcript Processing Only:** The LLM receives text transcripts from ASR. It is **not** an audio authenticity detector and does not process acoustic features.
3. **Strict Categorical Output:** The LLM must classify conversational risk into exactly one of three categories: `LOW`, `MEDIUM`, or `HIGH`.
4. **Fail-Safe Inconclusive Policy:** Any malformed JSON, unparseable risk level, empty input, timeout, or runtime failure must yield `INCONCLUSIVE`. It must **never** default to `LOW`.
5. **Mandatory TCED Rule Preserved:** Any `HIGH` classification triggers the mandatory suspicious-session override (`HIGH_RIAS_OVERRIDE`) in the Temporal Correlation & Decision Engine (TCED).
6. **Hardware Target:** Intel Core i5-1334U (13th Gen CPU, 16 GB RAM, Intel Iris Xe graphics). Primary evaluation executes strictly on CPU.

## 5. Semantic-Risk Evaluation Rubric & Prompt Configuration

### Evaluation Rubric
- **`LOW`:** Normal personal, social, commercial, or informational conversation with zero indicators of fraud, coercion, urgent financial demands, or credential phishing.
- **`MEDIUM`:** Ambiguous, unsolicited, mildly pushy, or unverified claims requesting callbacks, personal details, or unusual actions, but without extreme coercion or immediate irreversible fund transfers.
- **`HIGH`:** Clear high-risk social-engineering or harmful manipulation indicators: direct OTP/PIN/password solicitation, digital arrest threats, impersonation of police/CBI/TRAI/customs, urgent utility cutoff extortion, or remote-desktop app installations.

### Exact Version-Controlled RIAS System Prompt
```text
You are RIAS (Risk Identification and Assessment System), an advanced conversational security analyst integrated into CloudForge Intelligence Core (CFIC).

Your task is to analyze an audio transcript from an incoming telephone call to detect social engineering, urgency manipulation, extortion, financial coercion, impersonation (e.g. bank official, law enforcement, utility provider, family member in distress), and credential theft.

Evaluate the conversational risk into exactly one of three categories:
- LOW: Normal personal, commercial, or informational conversation with no indicators of fraud, coercion, urgent financial demands, or credential phishing.
- MEDIUM: Ambiguous, unsolicited, mildly pushy, or unverified claims requesting callbacks, personal details, or unusual actions, but without extreme coercion or immediate irreversible fund transfers.
- HIGH: Direct social engineering, urgent requests for OTP/passwords/wire transfers/gift cards, arrest threats, legal intimidation, emergency impersonation, or high-risk fraudulent instructions.

You must respond ONLY with a strict JSON object with no additional text or Markdown formatting:
{
  "risk_level": "LOW" | "MEDIUM" | "HIGH",
  "reason": "Concise summary of rationale (under 25 words)"
}
```

### Decoding & Runtime Parameters
- Engine: `llama-cpp-python` v0.3.36 (CPU execution)
- Threads: `n_threads=4` (Optimal for Intel i5-1334U core topology)
- Temperature: `0.0` (Strictly deterministic generation)
- Max Completion Tokens: `64` (Restricted to structured JSON object)
- Stop Tokens: `["\n\n", "}"]` (Halts generation immediately upon JSON closure)
- Context Window: `2048` tokens

## 7. Architectural Integration Prototype (RIAS Adapter)

To guarantee clean integration with the Cloud Inference Orchestrator without altering existing locked services, a temporary inference adapter was implemented at:
`cloud-inference/llm-evaluation/rias_adapter.py`

### Prototype Contract Specification
- **Request (`RIASRequest`):**
  - `session_id: Optional[str]` — Caller session tracking
  - `chunk_index: int` — Audio chunk index
  - `timestamp_start_s: float` — Window start time
  - `timestamp_end_s: float` — Window end time
  - `transcript: str` — ASR text
  - `language: Optional[str]` — Detected language code
- **Response (`RIASResponse`):**
  - `status: str` — `'success'`, `'skipped'`, `'inconclusive'`, or `'error'`
  - `risk_level: str` — Strict enum: `'LOW'`, `'MEDIUM'`, `'HIGH'`, or `'INCONCLUSIVE'`
  - `reason: Optional[str]` — Concise explanation (under 25 words)
  - `model_id: str` — Fully-qualified candidate ID
  - `model_revision: Optional[str]` — Exact Git commit SHA
  - `latency_ms: float` — Process inference latency
  - `session_id`, `chunk_index`, `timestamp_start_s`, `timestamp_end_s` — Preserved session metadata

### Fail-Safe Guarantee
If the input transcript is empty or whitespace-only, the adapter immediately returns `status="skipped"` and `risk_level="INCONCLUSIVE"`. If an inference error, timeout, or schema failure occurs, the adapter returns `status="error"` and `risk_level="INCONCLUSIVE"`. It **never** defaults an uncertain outcome to `LOW`.

The adapter was verified via unit tests (`cloud-inference/llm-evaluation/tests/test_rias_adapter.py`) with 8/8 tests passing.

## 13. Detailed Analysis & Trade-Offs

### Why Candidate B (Gemma-4-E2B-it) Wins
1. **Flawless Safety Record on High-Risk Fraud (Priority 1):** In real-time anti-fraud systems, false negatives on high-risk scams represent catastrophic safety failures (allowing an extortionist or credential phishing attacker through). Gemma-4-E2B-it detected **100% of all high-risk fraud cases**, including complex digital arrest, electricity disconnect threats, and bank KYC scams. Qwen3.5-2B missed 3 high-risk cases (downgrading them to MEDIUM).
2. **Substantially Superior Classification Quality (Priority 2 & 3):** Gemma scored **95.06% overall accuracy** and **0.8873 Macro F1**, outperforming Qwen (**82.72%** and **0.7138**) across both benign speech and suspicious telemarketing calls.
3. **Drastically Lower Inference Latency (Priority 6):** Gemma achieved a median latency of **3.06 seconds** per transcript on CPU, compared to **8.09 seconds** for Qwen. In an interactive telephone defense system where decisions must be rendered across 10-second audio chunks, a 3-second latency is viable, whereas an 8-second latency nears the chunk boundary.
4. **Significantly Lower CPU Utilization:** Gemma averaged **55.7% CPU load** during inference compared to Qwen's **88.3%**. This leaves over 44% of CPU resources free for concurrent execution of PellaV2 spoof detection, ASR decoding, and FastAPI routing.

### Trade-Offs & Cost of Candidate B
- **RAM Footprint:** Gemma consumes **2.79 GB peak RAM** compared to Qwen's **1.96 GB** (+833 MB). However, with 15.65 GiB system RAM, this trade-off is negligible and well within acceptable operating limits.
- **Model File Size:** Gemma requires **3.11 GB disk space** compared to Qwen's **1.28 GB** (+1.83 GB).

## 15. Known Limitations & Mitigations

1. **Medium-Class Sensitivity:** Both models occasionally classify aggressive telemarketing as HIGH or LOW rather than MEDIUM. *Mitigation:* In TCED policy, only HIGH triggers immediate suspension; MEDIUM is fused with acoustic spoof evidence, preventing false alarms.
2. **Long Audio Transcripts:** Transcripts exceeding 500 words require sliding window chunking to maintain sub-5s latency on CPU.
3. **Language Identification Coupling:** Both models rely on accurate upstream ASR text. If upstream ASR produces phonetic gibberish, the adapter gracefully falls back to `INCONCLUSIVE`.
